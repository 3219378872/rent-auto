# ADR-0011: 原持锁连接验证与失锁退出

日期：2026-09-08
状态：已接受

## 背景

会话级 advisory lock 只属于获取它的数据库连接。另取连接尝试加锁无法判别
原锁仍由本进程持有还是已被另一实例接管；普通池连接可用也不能证明原连接存活。

## 决策

- InstanceLock 保留原连接，检查原连接自己的 pg_locks/PID；错误或锁不存在永久标记失效。
- 每个调度任务入口先检查，另有 1 秒监控周期与单次 3 秒上限。
- 失锁立即取消进程根 context；所有手动任务虽脱离 HTTP 请求生命周期，仍绑定此根 context。
- Scheduler.Stop 后拒绝新的 Trigger/runDue，等待已开始任务退出，再关闭 HTTP 服务和进程。
- 失锁审计为有界 best-effort；审计失败不得阻止取消。

## 边界

本方案消除失锁后长期继续运营，不为已经到达远端平台的请求提供 fencing 或撤销。
网络分区检测存在周期/超时窗口；部署仍为单实例，不能据此扩展为多副本写入系统。
验证只终止隔离测试库内本测试的持锁 PID，不对生产连接做故障注入。
