# 前端用户体验审查与改进方案

日期：2026-09-19。状态：**本轮改进已实施并验证**。审查基线：`5a9b303`；实现提交：`2d50192`。

UX-01～15 的本轮目标已交付，UX-16 提供基本窄屏巡检兼容；完整门控与 Chromium 回归
见[修复证据](../evidence/2026-09-19-frontend-ux-remediation.md)。下文问题描述和分期估算保留为
审查时记录。单件/按筛选任务、逐次运行历史及补录历史策略版本/行情快照没有被虚构为已实现，
其边界见 ADR-0012。真实用户效率目标仍待业务使用验证。

目标是让单管理员在日常巡检时迅速回答三个问题：系统是否正常、商品为什么这样定价、下一步需要做什么。保持桌面优先、默认模拟执行、双渠道独立容错的产品边界。

本方案依据当前八个页面的源码、浏览器模拟数据复现及完整本地门控；不是生产业务或真实用户访谈结论。[复现报告与截图](../evidence/2026-09-19-frontend-ux-review.md)给出证据范围。[可交互布局原型](frontend-ux-prototype-2026-09-19.html)展示三个关键页面，所有数值及操作均为演示。

## 1. 结论与应保留的基础

现有页面具备清晰的七项侧栏导航、统一暗色样式、服务端分页、库存搜索、全量筛选结果 CSV 导出、策略参数说明、渠道异常条和可用的原生改密对话框。已有功能适合熟悉实现的人查看数据。

最主要的体验缺口集中在操作含义和状态反馈：筛选后的页面仍触发全局任务；输入中的数字被立即改写；模拟决策与真实执行结果难以辨认；页面把尚未加载的数据呈现为零；策略草稿和保存反馈容易丢失。应先补齐这些闭环，再调整布局和视觉层次。

本轮归并为 **16 项：P1 六项、P2 九项、P3 一项**。P1 表示可能导致误操作、错误输入或关键状态误判，需要优先修复；不代表已经发生资金事故。P3 的移动端适配是既有非目标之外的可选增量。

## 3. 页面方案与信息层级

维持现有七个主导航和 `/login`，首轮不增加主导航数量。页面内部用页签、详情抽屉和带上下文的链接减少来回查找。

| 页面 | 首屏应回答的问题 | 推荐布局与操作 |
|---|---|---|
| 登录 | 怎么进入、为什么失败？ | 用户名/密码可见标签、自动填充语义；错误留在字段附近；支持安全的站内返回地址。初始口令只给管理员获取路径说明，不读取或显示口令文件内容。 |
| 仪表盘 | 是否正常运行？今天有何变化？ | 顶部运行模式与数据时间；可操作告警；第一层 4 个关键指标，钱包/押金放资产分解；中层收益/订单趋势；下层任务最近结果与待处理事项。 |
| 库存 | 找到的是哪件实物？成本是否完整？ | 商品名+资产尾号、渠道/状态/搜索，新增成本缺失快捷视图；选中一行再编辑成本；详情关联货架、订单。物品图片是可选增强，当前 API 没有可靠图片来源时不强加。 |
| 货架 | 当前价格是什么？为什么变化？ | 默认在架，异常/不一致快捷过滤；价格与模拟建议分列；决策摘要可展开；全局任务按钮明确范围，单件能力交付后才出现单件操作。 |
| 订单 | 哪些需要关注，何时到期？ | 待处理、出租中、历史页签；商品先于长订单号；到期时间同时显示绝对值/相对时间；完整状态筛选；导出明确“当前筛选全部 N 单”。 |
| 策略 | 当前生效什么，我改了什么？ | 全局/模板/黑名单三页签；常用项优先，高级参数折叠但可搜索；参数以业务名称为主；固定保存栏与变更摘要；执行模式独立呈现。 |
| 渠道 | 哪个账号可用，怎样恢复？ | UU/ECO/Steam 三张状态卡，分别显示配置/校验/异常/未知；按需更新凭证；成功后留状态与指纹，不留敏感输入。 |


## 4. 关键交互细则

**列表状态**：初次加载保留标题/过滤器和占位行，不显示“0”；后台刷新可保留旧数据，但必须显示“正在更新，以下为上次结果”。无数据给出首次同步指引；筛选为空提供清除筛选；失败提供原地重试，保留筛选与已加载内容。异步旧响应不能覆盖新查询。

**任务执行**：确认文案明确对象、范围及执行模式；接口返回 triggered 只能显示“已受理”，任务状态来自 `/jobs`。现有 API 无逐次运行 ID 或逐商品结果，第一版仅展示任务名级别的运行状态；如需准确绑定这次点击与执行结果，新增 run ID/任务历史合同后再承诺。

**草稿与保存**：字段草稿、已保存值、服务端读取状态分开。普通参数保存后立即显示持久的就近反馈；按钮禁用期间文案说明原因。模板或黑名单操作刷新数据不能重置尚未保存的全局草稿。路由离开提示仅在存在更改时出现；敏感凭证永不写入 localStorage 草稿。

**模板继承**：每个参数显示“继承全局 30 分钟”或“已覆盖 60 分钟”，恢复继承删除该覆盖键。整个参数重置仍保留二次确认；明确“恢复内置默认值”与“恢复全局继承”的区别。路由、真实执行许可、优先级的实际规则照后端执行，不能显示虚假的继承状态。

**金额与说明**：金额统一两位小数和千位分隔，明确 `¥/天`、`¥`、`%`、`分钟`。参数帮助中“最低在售价”等表述应与实际租赁报价基线核对；显示业务名称，内部参数 key 放说明中。金融统计只改标签与解释时无需改算法，改口径必须另走规格与账本回归。

**决策记录**：至少给出时间、渠道/商品、模拟标记、结果、旧值/新值、跳过原因、当时记录的因子/V。当前成功分支存有 `reasons/v/factor`，跳过分支可能只有 `skip/reasons`；完整行情快照和策略版本并非每条历史记录都有，展示“历史未记录”，不得按当前策略伪造历史解释。

## 5. 实施依赖与后端边界

| 能力 | 当前基础 | 方案边界 |
|---|---|---|
| 加载/空/错误、保存状态、中文状态、数字输入、对比度 | 现有 React、共享 `usePagedList`、原生表单和 CSS | 首轮前端可完成，维持依赖体系；抽取必要状态组件，不引入整套新 UI 框架作为前置条件。 |
| 任务名级运行状态 | `GET /jobs` 有 running/last_run/last_ok/last_error/next_run | 前端可接；运行实例 ID、逐条执行结果、历史记录需后端扩展，原始错误先脱敏再展示。 |
| 有效执行模式与阻断原因 | `/strategies` 有行级开关，环境 `DRY_RUN_DEFAULT` 不在前端合同内 | 需要后端只读聚合字段，返回最终状态及环境/全局/模板限制；未知时不能显示“已开启真实执行”。 |
| 审计详情展开 | `/audit` 已返回 detail | 可纯前端实现；原始凭证和完整上游敏感错误不得因详情展开而暴露。 |
| 完整定价记录 | `price_actions` 已存部分决策/模拟/结果字段，无完整查询路由 | 新增鉴权、分页、时间/渠道/商品/模式/结果过滤的只读合同；先做字段库存盘点，缺策略版本/快照时再决定记录扩展及 ADR/迁移。 |
| 单件重定价、按筛选执行 | 现有按钮仅触发全局任务 | 首轮用明确范围修复歧义；后续新增明确目标的 API，复用策略、审计、冷却与 dry-run 门禁，不能在浏览器中绕过调度器。 |
| 库存品类/排序、订单名称/日期/排序、上下文查询 | 现有 `/inventory` 支持 channel/status/search；`/orders` 支持 channel/status | 扩展服务端查询、索引和总数合同；导出与列表同筛选，所有字段跨分页一致。 |
| 30 天订单数、观察期、数据新鲜度 | dashboard 有收益日序列，缺订单日序列/观察期/采集时间 | 需增加聚合/元数据；客户端请求成功时间只能标“页面获取时间”，不能当成平台同步时间。 |
| 模板/黑名单大集合搜索 | `/templates` 有可选分页，但返回数组无 total | 小集合可本地过滤；正式大集合方案增加搜索/total，不能把当前一页当成全集。规模验证采用合成数据另测。 |

涉及新 API 的项目先更新 `spec/openapi.yaml` 和对应验收标准；涉及持久化决策或调度语义时新增 ADR。上述是候选实施方向，本次不把它们当作已经采纳的架构决策。

## 6. 建议分期与工作量

工作量是单名熟悉项目的开发者的净工作日粗估，含针对性测试与证据归档，不是交付承诺；取决于 API 字段盘点、真实数据复杂度和评审结论。各阶段可单独交付，范围新增后重新估算。

| 阶段 | 建议工作 | 对应问题 | 粗估 | 交付门槛 |
|---|---|---|---|---|
| A：消除误操作 | 数字草稿、策略加载禁用保存、全局重定价范围、保存防重、健康失败提示、统一加载/错误/空态、固定保存栏与草稿保护 | UX-01/02/04/05/06；UX-03 先明确“模式未知/详情未接入”；UX-12 防重/清空 | 4–6 日 | 危险输入不改写、重复点击不多发、数据未知不装作正常；浏览器回归通过 |
| B：补齐运营闭环 | 有效模式 API、定价记录合同与界面、任务状态、模板来源、审计详情、订单完整状态；渠道恢复流程 | UX-03/07/10/11/12；UX-01 状态部分 | 6–10 日 | 能从异常找到对象、理解原因、执行操作并查到结果；历史缺失信息明确标注 |
| C：提高日常效率 | 资产/收入口径、趋势、查找排序、URL 状态、桌面表格和无障碍完善 | UX-08/09/13/14/15；UX-10 查询部分 | 4–6 日 | 1280 与 1440 桌面任务验收；搜索/排序/导出跨页一致；键盘任务可完成 |
| D：可选手机巡检 | 收起导航、告警/订单摘要、抽屉详情 | UX-16 | 2–3 日 | 需先将移动巡检纳入意图/非目标调整；不作为前三期上线阻塞 |

建议先落地 A；B 中的只读数据合同可同步细化。按钮标签、完整中文状态、可见标签和明确的单位等成本低的改动可随 A 交付，无需为等待整页重排而延后。

## 8. 实施后的用户验证

邀请实际管理员完成五个任务：判断当前是否会真实执行；找到一条失败或跳过的改价及原因；定位同名库存并修正成本；只覆盖一个模板参数再恢复继承；找出待发货/异常订单并导出当前筛选。

建议目标：运行状态识别不超过 10 秒，失败原因定位不超过 30 秒，成本和模板修改均无需离开面板查源码。记录任务成功率、时间、误操作与求助次数，以当前版本作对照。上述是待验证目标，本次没有真实用户样本，不报告虚构的满意度或效率提升百分比。

交付时运行 `make gate`，另补浏览器键盘、网络延迟/失败、多页导出、长名/同名/空数据与三种执行模式回归。门控、浏览器 mock、真实平台结果分别归档。
