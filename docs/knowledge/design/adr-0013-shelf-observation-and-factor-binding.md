# ADR-0013：货架观测边界与订单反馈归属

日期：2026-09-25
状态：已接受

## 背景

CQ-01 复现旧货架快照覆盖成功写回，CQ-02 复现一笔订单向历史/替代两条挂单折算。
同名任务防重及事务提交本身不能提供观测先后关系或唯一业务归属。

## 决策

- SyncShelf 在外部请求前读取数据库 clock_timestamp，随后以一个事务应用完整快照。
  upsert 与 missing 都检查 actual_synced_at、last_reprice_at 未晚于观测边界。
  上下架及改价写回用数据库 clock_timestamp，避免应用主机时钟偏差与事务开始时间误导。
  同渠道快照应用用事务 advisory lock 串行化，shelf_observations 水位拒绝倒序快照；
  不在网络请求期间持有数据库事务。actual_synced_at 对快照记录请求前边界，对写回记录写入时刻。
- confirmed delist/missing 写 retired_at，恢复在架时清空。时间仅作为本地观测界限，
  不宣称精确恢复平台实际下架时刻。
- 迁移 0011 引入订单 factor_listing_id、factor_observed_at 与 listings.retired_at。
  在订单同步事务中绑定唯一候选；尚无货架时，在反馈任务中重试。基于同渠道资产、模板
  与上市/退架时间约束寻找唯一候选，不选择“最新”行。未知开始时间允许唯一的本地
  历史候选，但不能使用退架时间反推出租时刻；歧义不折算，任务记录数量告警。
- 已绑定订单按 listing 主键读取；未绑定订单不消耗可执行反馈批次；保留订单级
  factor_applied 与因子更新同事务提交。提交前锁定订单并校验绑定与 updated_at，
  并发订单校订使旧计划整体回滚；未处理订单身份/开始时间被校订时重新解析归属。
  历史已应用事件不重放，不擅自重置存量因子。
- CQ-03 在完成 401 响应体解析后比较请求 tok 与当前令牌，相符才清除和跳转。

## 限制

没有可靠时间/身份的历史订单可能持续等待人工校订或上游补全。货架观测边界保护本地
并发写入，不能证明平台接口具备线性一致性；一次更新之后才发起的请求若由上游返回
缓存旧值，仍需平台版本信息才能识别。未新增平台调用或对外 API 字段。
